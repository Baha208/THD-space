# THD Space

THD Studio (interior design, Cairo) client presentations: one mobile-first web app per
client, used to walk them through floor plans and 3D renders on a phone or tablet.
Each presentation is a static PWA; there is no build step, framework or backend.

Alongside them, `hub/` is a separate installable app for the internal team ("THD Space"): a list
of all projects, plus Reports and News sections that are **placeholders only** (see Hub below).
Presentations never link to or mention the hub; the hub only links into them.

## project.json

Authored fields are written by hand; generated fields are overwritten by the script.

```jsonc
{
  "schemaVersion": 1,
  "slug": "inas-el-baily-villa",         // = folder name under projects/
  "client": "Inas El Baily",              // required (generator errors if empty)
  "title": "Inas El Baily’s Villa",       // required; shown in header, loader, <title>, manifest name
  "sourceDir": "3d views & working documents",
  "floors": [                             // order = tab order
    {
      "id": "ground",                     // unique in the project; used in DOM ids. --init makes
                                          // it from the full folder name: "ground-floor-level"
      "label": "Ground Floor",            // used in the gallery header ("Reception · Ground Floor")
      "tabLabel": "Ground",               // optional short tab text (falls back to label); keep it one
                                          // word so four tabs fit on one line at phone width
      "dir": "ground floor level",        // exact folder name on disk, case included
      "planDir": "floor plan",            // optional, default "floor plan"
      "plan": "…/Ground floor plan.webp", // GENERATED
      "rooms": [                          // order = button order
        { "id": "reception", "label": "Reception", "dir": "reception",   // id unique within its floor
          "images": ["…/reception1.webp", "…"],   // images GENERATED
          "medium": ["…/medium/reception1.webp", "…"] }   // GENERATED: copy per image, or null;
                                                           // absent when the room has no copies
      ]
    }
  ],
  "documents": {                          // PDFs shown in the "Drawings" tab
    "dir": "Working documents",
    "files": [                            // MERGED, not overwritten (see below)
      { "file": "…/Working documents/GF-electrical_layout.pdf", "label": "GF Electrical Layout" }
    ]
  }
}
```

Paths in project.json are relative to the project folder and stored raw (spaces, `&`);
app.js URL-encodes each segment. Room/floor ids exist only here — nothing else to keep in sync.

## generate-manifest.js

```
node engine/generate-manifest.js projects/<slug>              # fill project.json + write manifest.json
node engine/generate-manifest.js projects/<slug> --dry-run    # print result, write nothing
node engine/generate-manifest.js projects/<slug> --init       # new project: project.json + index.html + sw.js
```

- Re-run it whenever renders are added, removed or renamed. The app never guesses filenames.
  When renders change, run the medium-copy script instead: it makes the missing copies and then runs
  the generator itself (see below), so one command covers both.
- Images: every .webp/.avif/.jpg/.png in the room folder, natural sort (2 before 10). No renaming.
  Subfolders are not scanned, so a room's `medium/` copies never count as renders.
- Medium copies (needs sharp: once, from THD SPACE/, `npm install --prefix tools`):
  ```
  node tools/make-medium-renders.js projects/<slug>
  ```
  One command: it runs the generator with --dry-run to get the current render list, writes any
  missing copies, then runs `node engine/generate-manifest.js projects/<slug>` for real (writing
  project.json and manifest.json). It fails, writing nothing, while client/title are empty.
- `medium`: for each image, "<room>/medium/<same name>.webp" if that file exists, else null. The
  copies come from tools/make-medium-renders.js (long edge 1500 px, WebP q80; originals of 1600 px or
  less get none). It never touches originals, skips copies that exist unless the original is newer,
  and warns instead of overwriting when two originals (a.jpg + a.webp) would share one copy.
- Folder names must match the disk **exactly** — Windows ignores case, production hosting doesn't.
  The script errors on a case mismatch or missing folder and writes nothing.
- New folders not yet in project.json are appended as rooms with a warning; fix their label/order.
- `--init` guesses labels and orders floors alphabetically — always review before publishing.
  It writes index.html and sw.js from engine/templates/ (never overwriting existing ones) and
  skips manifest.json until client/title are filled in. Outside `--init`, an empty client or
  title is an error.
- Duplicate ids are an error: floor ids across the project, room ids within a floor.
- Documents: only `.pdf` files in `Working documents/` (others are skipped with a warning). New PDFs
  are appended with a label from the filename ("GF-electrical_layout.pdf" → "GF Electrical Layout";
  all-caps words kept). Existing labels are never overwritten, so edit them freely. A listed PDF
  that's gone from disk is warned about but **kept** — delete its entry by hand if that was intended.
- manifest.json colors come from `--ink` in engine/tokens.css; icons point into engine/images/icons/.
  "maskable" entries use icon-maskable-192/512.png (mark inside Android's 80% safe circle, on ink);
  every other entry is the edge-to-edge icon-<size>.png. The maskable files are committed assets,
  made once from icon-512.png; to remake them (e.g. new logo): `npm install --prefix tools` once,
  then `node tools/make-maskable-icons.js` (from THD SPACE/). They are shared, not per project.

## New client

Run every command from the `THD SPACE/` folder. Needs Node 18+.

1. Create `projects/<slug>/` with the `3d views & working documents/` tree (floor → `floor plan/` +
   room folders). `Working documents/` is optional until there are drawings to add.
   Renders and floor plans can be `.webp`, `.jpg`/`.jpeg`, `.png` or `.avif` (any letter case;
   formats can be mixed in one room). Step 5 makes a `.webp` medium copy from any of them. The
   originals are shown as they are when zoomed, so prefer `.webp` or `.jpg`: `.png` is large, and
   `.avif` doesn't display on iPhones older than iOS 16. Two originals with the same name in one room
   (`a.jpg` + `a.webp`) would share one copy, so step 5 skips the second with a warning — rename it.
2. `node engine/generate-manifest.js projects/<slug> --init` — writes project.json, index.html, sw.js.
3. In project.json, fill in `client` and `title`; check floor order, ids and labels.
4. Only once per computer (skip if `tools/node_modules/` already exists): `npm install --prefix tools`
5. `node tools/make-medium-renders.js projects/<slug>` — makes the medium copies of the renders, then
   runs `node engine/generate-manifest.js projects/<slug>` itself, which adds the `medium` lists to
   project.json and writes manifest.json. Nothing else to run.
   (If sharp can't be installed: run `node engine/generate-manifest.js projects/<slug>` instead. It
   writes manifest.json; the gallery then opens the full-size originals, which just load slower.)
6. `node tools/generate-projects-index.js` — adds the project to the hub's Projects list
   (projects-index.json) and refreshes hub/manifest.json's colours. Plain Node, no install needed.
7. Serve the root and open `/projects/<slug>/` (or tap it in the hub at `/hub/`).

Later changes: renders added/removed/renamed → step 5 again. Only labels/order/PDFs changed →
`node engine/generate-manifest.js projects/<slug>` is enough (step 5 also works). Project added,
removed, or its folder/client/title changed → step 6 again.

## Hub (hub/)

The team's own installable app, "THD Space". Separate from the presentations in every way: own
manifest, own service worker and caches, own icons. It shares only engine/tokens.css (colours and
fonts) with them. Nothing in engine/ or projects/ links or refers to it — keep it that way, so a
client presentation never exposes internal pages.

- Bottom tab bar (the app's top-level sections; distinct from the floor tabs inside a presentation):
  **Projects** (default), **Reports**, **News**. The open tab is in the URL hash with
  replaceState, so reloads keep it and switching tabs adds no history entries. Text only, no logo
  in the chrome (same rule as the presentations: the install icon is the branding).
- Page zoom is fully locked, as in the presentations: the viewport meta has maximum-scale=1 and
  user-scalable=no, `html` has touch-action: pan-x pan-y (no double-tap zoom), and hub.js blocks
  iOS's gesturestart/change/end and two-finger touchmove (iOS ignores user-scalable=no). The hub
  has nothing that needs zooming, so unlike the presentation gallery there is no scoped zoom.
- Zoned colours, using the shared zone tokens from engine/tokens.css (see Conventions → Zones):
  header and bottom tab bar `--chrome-bg`; header title `--chrome-text`; the "THD SPACE" kicker
  and inactive tabs `--chrome-text-muted`; content area `--content-bg`, full height on every tab
  (placeholders too); project rows are cards (`--card-bg`, 1px `--card-border`,
  `--card-hover`) — future Reports/News items should reuse the same card treatment; active tab
  `--chrome-text` with the accent bar on its top edge, as the floor tabs. `html`/`body` are
  `--chrome-bg` too, so iOS overscroll matches the chrome.
- Status bar: installed on iOS the hub uses `apple-mobile-web-app-status-bar-style`
  black-translucent (with viewport-fit=cover), so the ink header runs up under the clock and
  battery; the header pads its top by `env(safe-area-inset-top)` and the tab bar its bottom by
  `env(safe-area-inset-bottom)`, so the kicker/title and tabs never sit under the status bar or
  the home indicator.
- Safe areas after a round trip to a project: in the installed hub on iOS, tapping a project opens
  it in the in-app Safari sheet over the still-running hub (no reload), and after Done the header
  was seen under the notch again, although a fresh open was fine. Only the reported
  `env(safe-area-inset-*)` values can change without a reload, so the likely cause is WebKit
  leaving them at 0 after the sheet (which owns the status bar) is dismissed, until the next
  viewport change; iOS may fire no event on that return. Fix (hub.js "SAFE AREAS" + the top of
  hub/styles.css): a hidden probe measures the insets on load and on resize/orientationchange/
  pageshow/focus/visibilitychange, remembers the largest per orientation for the session, and the
  CSS pads with max(live env(), remembered) via --sa-top / --sa-bottom. It needs no event on the
  return, never adds the two, and landscape keeps its own values. Checked in Chrome only by forcing
  the emulated insets to 0 without an event; **not yet confirmed on an iPhone round trip** — if it
  still happens there, the next thing to try is re-applying the viewport meta on return to make
  WebKit recompute the insets.
- **Opening animation** (hub only; a presentation's loader does real loading work and stays as it
  is): on ink, three thin accent rings pulse outward (staggered), the "THD" mark
  (hub/splash-mark.png: the same extracted mark as the icons, top line only, accent) fades and
  scales in over the first third, then "SPACE" (accent, small, wide tracking) fades in below;
  ~1.5s, then a 0.3s fade reveals Projects. Flat colours only (no blur, no gradients). It always
  plays to completion once it starts: taps and keys during it do nothing (there is no skip).
  Deliberate behaviour — don't "fix" it into always playing:
  - **Cold start only**, tracked in **sessionStorage** (key `thd-hub-intro`), deliberately not
    localStorage: it plays when the app is freshly launched (a new session), never when it is
    resumed from the background during the day, reloaded, or returned to from a project in the
    same session. An inline script in index.html's <head> decides before the first paint (adds
    `html.intro-playing`), so a non-cold start never even flashes it.
  - Reduced motion: no rings or scaling; the mark and word show still for ~0.9s.
  - The `html` flag class is `intro-playing`, not `intro`: `.intro` is the overlay's own
    class (display: none by default), and sharing the name hid the whole page.
- Projects: reads `../projects-index.json` and shows one row per project (title, client), each a
  plain link to `../projects/<slug>/`. That is a normal navigation out of the hub's scope, so the
  project's own service worker takes over there. In the installed hub, iOS/Android show the project
  in an in-app browser view with a Done/close control back to the hub. The hub's scope is only
  hub/ on purpose: a site-wide scope would open projects inside the hub window, where iOS has no
  back gesture and presentations have no link back. A missing or broken index shows an inline
  error with its path.
- **Reports and News are placeholders pending further direction**: a static "Reports — coming
  soon" / "News — coming soon" screen each. There is deliberately no data file, schema or loading
  code for them. Don't treat them as features or invent a structure without a brief.
- generate-projects-index.js scans every folder in projects/ and lists it when project.json parses,
  its "slug" equals the folder name, client and title are filled in, it has floors, and the folder
  has index.html; anything else is skipped with a warning saying why. Entries `{ slug, client,
  title }`, sorted by title. Rerun it whenever a project is added, removed or renamed, or its
  client/title changes (the hub never scans folders itself — a static host can't list them).
  It also sets hub/manifest.json's "theme_color" and "background_color" from --ink in
  engine/tokens.css (the same rule generate-manifest.js applies to each project's manifest),
  leaving every other field there as authored. So after changing --ink, rerun it too.
- Service worker (hub/sw.js, scope hub/): precaches the hub files (splash-mark.png included, so the
  intro works offline), its icons, engine/tokens.css,
  the two fonts it uses and projects-index.json, so the tabs and the project list work offline
  after one visit. Hub files and the index are network-first (a new index shows up when online);
  tokens/fonts stale-while-revalidate. Its caches are named `thd-hub:<scope>:<VERSION>` and never
  touch a project's. **Bump `VERSION` in hub/sw.js whenever a hub file changes** (independent of
  engine/sw.js's VERSION).
- hub/manifest.json: name, scope, display and icons are written by hand; its two colours are
  generated from engine/tokens.css by generate-projects-index.js — don't edit them by hand.
- **Icons are a placeholder treatment, not a final design decision**: the THD mark from
  engine/images/icons/icon-512.png recoloured to ink, on a full-bleed accent-yellow (#FEFB28)
  square, so it can't be confused with a client presentation's ink icon on the same phone. The
  "any" icons keep the mark's size/position from the project icons; the maskable ones fit it in
  the 80% safe circle. Remake with `node tools/make-hub-icons.js` (after `npm install --prefix
  tools` once), or replace the files in hub/icons/ when real artwork exists.

## Runtime behavior

- Loader waits only for project.json, fonts and the **first** floor plan. Other plans load in the
  background; a room's renders load when the room is opened (gallery prefetches next/previous).
- Failures are never silent: a missing project.json / first plan stays on the loader and lists each
  path; a missing later plan or render shows an inline error with the path, and logs to the console.
- Zoom (zoom.js, used by the gallery and the drawing viewer) is a CSS transform on one element —
  the page viewport never zooms. Pinch / double-tap (touch), wheel / double-click (mouse), max 4x.
  Zoomed in, a drag pans (clamped so the content keeps covering the screen). Gallery: the render
  zooms; swipe-to-navigate only at 1x; zoom resets on every image change, close, and rotation.
- Progressive renders (gallery.js): a render opens as its medium copy; once that is on screen the
  original is fetched and decoded in the background. Zooming past 1x swaps in the original (with the
  image box locked, so nothing moves), back at 1x the medium copy returns. A missing medium copy falls
  back to the original silently; the original failing while zoomed keeps the medium copy. Neighbours
  are prefetched as medium copies.
- Back button: opening the gallery or the drawing viewer pushes a history entry (history.js), and
  Android back / iOS swipe-back pops it and closes the overlay instead of leaving the app. Closing any
  other way (×, Escape, backdrop) removes the entry with history.back(); that popstate is recognised
  and ignored, so back never needs pressing twice and close never runs twice. A reload with an
  overlay open neutralises the stale entry.
- Drawings tab (after the floor tabs): lists documents.files by label, or "No drawings yet". Tapping
  one fetches it (so failures show inline with the path), then shows it in a full-screen in-app
  overlay (app.js "viewer": dark backdrop, close button, Escape, focus back to the link). Not an
  `<iframe>` (iOS shows only page 1 of an embedded PDF and can't zoom it) and not a new tab (a
  target="_blank" in an iOS home-screen app opens in the app's webview with no way back).
  pdf-view.js hands the fetched bytes to PDF.js (imported on first use) and stacks one `<canvas>`
  per page in a scroll container. Every page gets a sized placeholder; pages are drawn only within
  one screen of view and freed further away. Zoom applies to the whole page stack: at 1x the stack
  scrolls natively (plain mouse wheel scrolls; Ctrl+wheel / trackpad pinch zooms), zoomed in a drag
  pans, and zooming out turns the pan into scroll position. When a zoom settles, pages in view are
  redrawn at the zoomed resolution, capped at 8 MP per canvas (iOS canvas memory).
- PDF.js's worker starts from a same-origin blob that imports engine/pdfjs/pdf.worker.min.js, so the
  worker belongs to the page and its requests go through the project's service worker (a worker
  loaded straight from engine/ would be outside its scope and fail offline). If a worker can't
  start, PDF.js runs the same file on the main thread.
- Service worker (scope = project folder): precaches the engine shell, project files and floor plans
  on install; renders and PDFs are cache-first as viewed (PDFs in their own cache, never precached),
  so anything seen once works offline. PDF.js has its own cache named after `PDFJS_VERSION`
  (survives VERSION bumps); pdf.min.js + pdf.worker.min.js are precached when project.json lists
  drawings, fonts/wasm are cached as used. PDF navigations are routed before the app-shell rule, and
  only full 200 responses are cached. **Bump `VERSION` in engine/sw.js whenever engine files change.**
  Updating PDF.js: replace engine/pdfjs/ from the pdfjs-dist `legacy/` build (keeps older iOS
  working), rename the two .mjs files to .js (not every host serves .mjs as JavaScript), and change
  `PDFJS_VERSION` in sw.js.


## Cloud serving and admin panel

Proof of concept for running THD Space without a developer in the loop: the presentation
engine and the hub are unchanged; only where a project's content comes from changed. Instead of
a folder in `projects/` committed to git, a project lives in one R2 bucket and is served by a
Pages Function at the same URLs, and the admin panel writes it there. The old folder workflow
still works on any static host, and `tools/import-project.js` moves a folder project into the
bucket.

- **The bucket** (wrangler.toml binding `BUCKET`): `projects/<slug>/project.json`, the project's
  files at the paths project.json lists (`projects/<slug>/<path>`), `projects-index.json` (the
  hub's list: published projects only, sorted by title, the same entries
  generate-projects-index.js writes) and `templates.json`. Locally wrangler emulates it under
  `.wrangler/state/`.
- **project.json** is the same schema plus admin-only fields the engine ignores: `status`
  (`draft` | `published` | `deleted`), `createdAt`, `updatedAt`, `templateId`. Floors and rooms
  made in the panel have no `dir` (only the generator uses it). Uploaded files are stored as
  `floors/<floorId>/plan-<name>.webp`, `floors/<floorId>/<roomId>/<name>.webp` with the medium
  copy in `medium/`, and `documents/<name>.pdf`; names carry a random suffix so a replaced file
  never reuses a path (the presentations cache images by path, forever).
- **Serving** (server/serve-project.js, routes in functions/projects/): `/projects/<slug>/`
  returns engine/templates/index.html with `{{ENGINE}}` filled in, `sw.js` the template worker
  stub, `manifest.json` is built from the title and `--ink` (same rule as generate-manifest.js),
  `project.json` and every other path come from the bucket. `/projects/<slug>` redirects to the
  slash form (the shell's URLs are relative). Drafts are served (that is the preview); a deleted
  project is a 404 naming the path. Same origin, so the project service worker, its caches and
  offline behaviour are exactly as before. Only `/projects/*`, `/projects-index.json` and
  `/admin/*` reach Functions (site/_routes.json); engine/ and hub/ are plain static files.
- **Status lifecycle**: a project is created as a draft; **Publish** runs the engine's own
  start-up checks (every floor has a plan, every room at least one render, from
  engine/app.js validate()) and refuses with the list of what's missing, so the hub never lists
  a presentation that would open on the loader's error list. Unpublish returns it to draft. Move
  to trash sets `deleted`: it leaves the hub and its URL stops, files stay in the bucket, Restore
  makes it a draft again. Nothing is ever hard-deleted from the panel (a purge is a manual job).
- **Validation** (server/project.js) ports the generator's rules: unique floor ids in the
  project, unique room ids per floor, non-empty labels, safe relative paths (no `..`, no
  reserved names), `.pdf` only for drawings. Ids are made the way the generator makes them from
  folder names (slugify for floors, camelCase for rooms), with `-2`, `-3` on collisions.
- **Admin API** (functions/admin/api/, JSON): `GET/POST projects`, `GET/PUT/DELETE
  projects/<slug>` (PUT saves the whole project; it cannot change status or createdAt; it creates
  the project when missing, which is how the import tool works), `POST projects/<slug>/status`
  `{ status }`, `PUT/DELETE projects/<slug>/files?path=` (raw body; also `{ paths }` for
  batches), `GET/PUT templates`, `GET me`. Errors are JSON `{ error, details? }` with the right
  status (400/404/409/413/422). Uploads are read into memory, 100 MB cap.
- **Admin panel** (admin/): laptop-first, phone-usable; ink chrome + section tabs (the
  presentation's floor-tab treatment), mist content, white cards; only tokens.css colours.
  Projects list (published / drafts / trash), New project (client, title, slug made from the
  title, template), editor (details, floors with plan upload, rooms with render upload by drop or
  picker, drawings, reorder with arrows, preview link, publish, trash), Templates. Every change
  saves itself after 0.8 s, and each upload saves the project the moment it lands. Images are
  resized in the browser before upload the way tools/make-medium-renders.js does on disk:
  original capped at 3000 px (a JPEG/WebP already under the cap is uploaded untouched), medium
  copy 1500 px WebP q80 when the source is over 1600 px. Modern browsers only (unlike the engine
  and hub, it uses current JS). Not a PWA and served `no-store`, so it is never stale.
- **Templates** are only the starting shape of a new project: floors with room labels, no
  images. Seeded from server/templates-default.js (Villa, Apartment, Duplex, Blank: room names
  are a first guess, edit them in the panel) into `templates.json` on first read. Changing a
  template never touches projects already made from it.
- **Login** is Cloudflare Access in front of `/admin/*` (a dashboard setting, below), verified
  again inside functions/_middleware.js (server/access.js checks the Access JWT signature,
  issuer, audience and expiry against the team's published keys). With `ACCESS_TEAM_DOMAIN` and
  `ACCESS_AUD` unset, as in local dev, the panel is open and reports "local-dev". There are no
  users or roles in the app itself: whoever passes Access can do everything.
- **Local lab**: `npm install` once, then `npm run dev` (builds dist/, starts wrangler on
  http://localhost:8788 with the emulated bucket). `node tools/import-project.js
  projects/inas-el-baily-villa` puts the villa in. Files in admin/, hub/, engine/ need
  `npm run build` to reach dist/; functions/ and server/ reload on their own. `npm test` runs
  the server unit tests (node:test).

### Deploying

1. Make the GitHub repo private (client renders are in it) and connect it to a Cloudflare Pages
   project: build command `npm run build`, output `dist/`, root `/`. Or from a laptop:
   `wrangler login` once, then `npm run deploy`.
2. Create an R2 bucket named `thd-space` (wrangler.toml) and bind it to the Pages project as
   `BUCKET` (Settings > Bindings) for production and preview.
3. Protect the panel: Zero Trust > Access > Applications > add a self-hosted application for the
   site's hostname with path `admin` (and one for `hub` if the hub should need a login too), an
   allow policy listing the team's emails. For the free `*.pages.dev` hostname: Pages project >
   Settings > "Enable access policy", then remove the wildcard from the generated application's
   subdomain so it covers the production hostname too (Pages docs, "Known issues"). A custom
   domain needs its own Access application or the login screen renders but does not work.
4. Copy the application's AUD tag and the team domain into the Pages project's variables:
   `ACCESS_AUD`, `ACCESS_TEAM_DOMAIN` (e.g. `thd.cloudflareaccess.com`). Without both, `/admin/`
   is open: never deploy it that way.
5. Put the villa in: `CF_ACCESS_CLIENT_ID=… CF_ACCESS_CLIENT_SECRET=… node
   tools/import-project.js projects/inas-el-baily-villa --server https://<site>` with a Zero
   Trust service token allowed by the Access policy. Rerunning is safe.
6. Backups: R2 has no versioning. The trash is a status flag, files are kept, but a purge or a
   bucket mistake is final: schedule an export (`wrangler r2` or rclone) somewhere else.

## Conventions

- Brand tokens live only in engine/tokens.css `:root`: ink #231F20, ink-soft #3E393B, gray #616161,
  mist #E9ECEB, accent #FEFB28 (+ white, error). engine/styles.css and hub/styles.css both
  @import it and define no colours of their own.
- Zones (engine/tokens.css, built only from the colours above; used by the presentations and the
  hub alike): `--chrome-bg` (ink) for header and tab bars, `--chrome-text` (white) for titles and
  the active tab, `--chrome-text-muted` (white mixed 55% into ink) for chrome labels and inactive
  tabs, `--chrome-divider` (hairline inside the chrome), `--content-bg` (mist) for the area
  between the chrome, and white cards on it: `--card-bg`, `--card-border` (ink at 12%),
  `--card-hover`. In a presentation: the header and the floor tab bar (Drawings included) are
  chrome; the panels and footer are content; the floor plan, room rows and drawing rows are cards
  (8px apart); the active floor tab keeps the accent bar on its bottom edge. The gallery, the
  drawing viewer and the loader are not zoned (dark overlays / white loader, unchanged).
  Change a zone in tokens.css, never with local colours in a stylesheet.
- Status bar and safe areas (presentations and hub alike): index.html uses
  `apple-mobile-web-app-status-bar-style` black-translucent and `viewport-fit=cover` (in
  engine/templates/index.html too, so new projects get it), so installed on iOS the ink chrome runs
  up under the clock with no white strip. engine/styles.css ("SAFE AREAS") defines --sa-top/right/
  bottom/left from env(safe-area-inset-*) and pads everything that could end up under the status
  bar, home indicator or landscape side notch: header (top + sides), floor tabs (sides), content
  and footer (sides, footer bottom), gallery close button/stage/arrows/caption, drawing viewer
  close button/pages/caption. The sticky floor tabs stick at `top: var(--sa-top)` (not padded, so
  there's no empty band above them under the header), and a fixed ink `body::before` strip the
  height of the status bar sits behind it so content scrolling up never shows under the clock.
  The loader (white, full screen) covers that strip while loading. Every inset is 0 on screens
  without a notch, so desktop/Android layout is pixel-identical to before. Any new element placed
  at a screen edge must use the --sa-* values the same way. No raw colors elsewhere; theme-color meta is set
  by app.js / hub.js from `--ink`, manifest colors by scripts (generate-manifest.js for each project,
  generate-projects-index.js for hub/manifest.json). After changing a colour token, rerun both.
- Fonts: BankGothic for display (uppercase, tracked), Inter for body, declared once in
  engine/tokens.css (font URLs are relative to it, so they resolve to engine/fonts/ from any
  importer). All self-hosted — no CDNs, so the apps work offline.
- Studio-wide copy ("interior design" kicker, "THD Studio — Cairo, Egypt" footer) lives in the
  STUDIO constant in engine/app.js.
- No THD logo inside the app: the loader and header are text only (kicker + title; centred title).
  The mark is seen on the home-screen icon (favicon, apple-touch-icon, manifest icons), which is
  where branding belongs; don't add it back to the loader/header.
- Plain browser JS (IIFEs, no modules, no dependencies). The one exception is PDF.js, vendored in
  engine/pdfjs/ and loaded with `import()` only when a drawing is opened. The Node script needs only
  Node 18+.

## Known open items

- Admin-panel POC: the villa still lives in `projects/` in git as the import source; once it is
  in the production bucket and backed up, the folder can leave the repo (a separate, deliberate
  commit). Drafts are reachable by URL (preview) without a login; presentations have no login at
  all and slugs are guessable. `projects/[slug].js` duplicates the catch-all route's empty-path
  case (wrangler matched the catch-all first) and is kept as a safety net. Tested locally with
  wrangler only; not yet deployed, and Access not yet exercised end to end.
- Viewport disables page pinch-zoom (`user-scalable=no`); only gallery images zoom.
- Zoom and the canvas drawing viewer are tested in desktop Chrome with touch emulation, not yet on
  a real iPhone (iOS ignores `user-scalable=no`; zoom.js blocks its `gesturestart` to compensate).
- Drawing pages have no text layer: text in a PDF can't be selected or searched, and links in it
  don't work. Very large sheets zoomed to 4x hit the 8 MP canvas cap and soften slightly.
- Renders: originals ~2500–3300 px (~480 KB avg); medium copies ~180 KB avg. No thumbnails yet.
- Serving the whole root also publishes `THD studio brand identity/` and `tools/` (with its
  node_modules) — exclude both when deploying. Deploy engine/, projects/, hub/ and
  projects-index.json. The hub is then reachable by anyone who knows /hub/ (it has no login); it
  only lists project titles and clients, but keep that in mind before adding internal content.
- Hub: tested in desktop Chrome (installability, offline, tab bar) and installed on an iPhone via a
  temporary tunnel (icon distinct from the villa's, Done view back from a project, tabs, offline
  reopen all fine). Not yet tried on Android. The zoned colours, zoom lock, status bar and opening
  animation (hub-v4) are tested in desktop Chrome with touch emulation only, not yet on the iPhone.
